Phase 5 has started with independent owner tools. It is not complete. Phase 3 acceptance remains owner-deferred while Netlify capacity is exhausted; Phase 4 is incomplete. ## Implemented scope

- A responsive Studio workspace with Overview, Catalogue, Trust and enquiries, Custom gift requests, Owner audit and Security, showing only sections supported by existing flags. Overview provides task shortcuts without fabricated analytics. Sections load on their first visit and remain mounted afterward, preserving unsaved values while switching sections. Focus moves to the selected section heading. Existing product, media, taxonomy, settings, review and enquiry controls retain their server authorization and confirmation flows. The existing authenticator flow is placed in Security; owner/MFA setup is not recreated.
- A read-only owner audit endpoint and viewer, requiring active owner role, aal2 and authenticator verification within five minutes in both BFF and transaction guards. Editor, customer, guest, aal1, stale-MFA and revoked-owner access are denied. No browser-role table/function grants are added.
- Searches use Kolkata calendar-day boundaries with a maximum 90-day window, action prefix, record type and exact record/request UUID filters. Fifty entries per page, one additional entry to detect another page, timestamp/UUID keyset cursors and an as-of timestamp keep paging bounded and exclude records timestamped after the cutoff. This timestamp anchor is not a cross-request MVCC database snapshot; concurrent backdated/in-flight commits still need the deferred hosted race checks. No total-count or background-polling query is issued. Manual refresh starts a new snapshot.
- The response explicitly projects audit event ID/time, actor kind, safe action/entity tokens, record/request references and allow-listed numeric version/count and boolean configured metadata. Actual zero and false are retained. Unknown fields, nested diffs, arbitrary values, session actor identifiers, session entity IDs and credentials/contact data are withheld. Unsafe action/entity strings become `other`. This is a foundation over the audit data already written; it does not invent missing before/after values or certify complete action coverage. The viewer has no mutation or export endpoint.
- Audit records clear on failed loading/verification. Search values/cursors and unsaved settings remain only in React memory, with no browser-storage persistence. Existing private/no-store and noindex boundaries remain. The original workspace stays available when the new flag is off.
