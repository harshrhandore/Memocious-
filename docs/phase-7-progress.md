## Corrected in this increment

- Login return paths are validated again after browser URL normalization. `/shop/../../api/admin/workspace` previously passed the initial route-prefix check; it now falls back to `/account`. This was an unintended internal redirect, not evidence that destination authorization was bypassed. Permitted normalized destinations and ordinary product/order links still work.
- JSON mutations require the actual `application/json` media type, including legitimate parameters. Lookalikes such as `application/jsonp` no longer pass the format guard. Exact origin, cross-site rejection, CSRF, body-size limits and strict payload schemas remain required.
- Auth, public catalogue and privileged database/Storage clients share a 10-second fetch deadline, preserve Request/init cancellation and force `no-store`. The wrapper does not retry mutations. A timeout can leave a server transaction's outcome uncertain; reconciliation and idempotency remain necessary. A timeout is never a confirmed rollback. This is a per-fetch bound, not a total multi-call handler budget.
- Global `Referrer-Policy` is `no-referrer`, consistent with existing API/callback overrides and password-reset metadata. Private routes and callbacks retain no-store. Cookie scope, MFA, RLS and grants were not relaxed.
- CI now runs pinned Semgrep CE with OWASP Top Ten registry rules, fails on findings/configuration errors and retains its report for seven days. Registry availability is necessary; merely fetching rules is not a successful scan. Registry contents can evolve between runs.
