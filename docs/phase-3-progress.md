# Latest increment: private builder reference images

The builder now uses the reserved request_uploads/upload_tickets/upload_jobs lifecycle. Verified customers can reserve an exact immutable private path against a saved schema-2 draft, upload a still image through bounded ingress, and view only the normalized WebP after full server decode/re-encode. Actual bytes must match the reservation; one-use tickets, parent versions and a two-minute processing lease prevent reuse/stale attachment. JPEG/PNG/WebP are allowed, SVG/active files and HEIC require rejection/conversion. Five files per draft, 20 reservations/day and 100 retained files/100 MiB per builder user are enforced transactionally. The current ingress deliberately tightens the specification's proposed 5 MiB maximum to 2 MiB/file (and at most 10 MiB for five ready inputs), below the 25 MiB per-draft ceiling, to fit the existing host path.

The Photos step offers file/drop/camera inputs, ephemeral local preview, an optional centre-square crop, transport progress, stop, retry/status refresh, private saved previews and explicit removal. Browser cropping is convenience only; the server still performs all validation and EXIF removal. Ready acknowledgement updates the parent version. Local edits are preserved if a draft changed during processing; server metadata is never silently used to overwrite a different payload. Type/base-gift changes and field reset are disabled until active reference images are explicitly removed. Required-photo gifts can proceed only with a ready sanitized file. Quote submission is still disabled in this increment.

No builder publication/signature endpoint exists. Preview is same-origin authenticated, owner/customer-authorized and private/no-store, bypassing the shared image optimizer. Removing a file or cancelling a draft revokes subsequent application access; physical deletion is reconciled after a one-day grace to avoid late writes, and cannot recall downloaded bytes. Successful normalized uploads delete unnecessary quarantine originals immediately when possible; the scheduled worker retries missed quarantine deletions. Expired/cancelled drafts are purged only after all referenced objects and job/ticket metadata have been reconciled. Closed custom-request file retention is reserved at 90 days; its real scheduling/provider execution remains unverified.
